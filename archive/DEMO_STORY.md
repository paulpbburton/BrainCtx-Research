# The team was available. Nobody asked.

> **Status:** completed demonstration readout
> **As of:** 2026-08-08
> **Authority note:** The private record is authoritative; this repository is the legible surface.

## Hypothesis

A live team might convert parked uncertainty into action. If an agent had an
announced visual expert, research seat, and supervisor available during work,
then a missing capability already named in its own files might become a
question, a reply, an implemented choice, and an evaluated result. This was a
demonstration of that mechanism, not a powered effect estimate. (Anchor:
`ABL04-DEMO-01`)

## Result

The obvious remedy did not work.

Across four store-plus-live-team runs:

- voluntary asks: 0;
- replies: 0;
- explicit reply citations: 0;
- seat inference use: 0;
- complete ask/reply/use chains: 0;
- measured activation of the target route: 0/4; and
- sealed primary endpoint passes: 0/4.

The agents nevertheless documented relevant uncertainty and absent routes in
their own work. Three announced seats went unused. The observation is narrow:
there was no matched no-team condition in this demonstration, so it does not
estimate a team effect or show that a reply would have improved the artifact.
It shows that availability did not activate voluntary consultation in these
four runs. (Anchor: `ABL04-DEMO-01`)

## Why the null sharpened the program

The result separates three ideas that are easy to blur:

1. uncertainty can be written down;
2. help can be available; and
3. help can actually be sought and used.

The first two occurred. The third did not. A margin note about a missing
capability is useful evidence, but it is not consultation. That moves the next
question from “does a channel exist?” to “which expectation or system action
converts recorded uncertainty into a real exchange?” (Anchor: `DEMO-LESSON-01`)

## The expectation ladder now in design

| Rung | Institutional treatment |
|---|---|
| T1 — Available | Seats exist and are announced. This is the demonstrated zero-ask condition. |
| T2 — Expected | Consultation is expected when a seat's competence applies; declining requires a written reason. |
| T3 — Observed | The agent is told that consultation behavior is recorded. |
| T4 — Teamwork graded | Collaboration quality becomes a named outcome. |
| T5 — Coworker report | The agent knows the seats will later report their observations of the collaboration. |
| T6 — Supervisor initiates | In-run supervision can compose a question from uncertainty the agent already wrote and route it to the relevant seat. |
| T7 — Expert comparison | The agent knows its result will be compared with an expert result and that unconfirmed uncertainty may leave useful evidence unused. |

The ladder is a preregistered design direction, not a seven-arm result. The
study will select a tractable subset of rungs while preserving the full ladder
for later work. (Anchor: `ABL05-01`)

## Cascaded consultation

The proposed T6 mechanism listens at major work transitions for uncertainty
already expressed by the agent—for example, an absence declaration followed
by continued implementation. When a registered pattern appears, the system
forms the question the agent did not ask, using only the agent's own words,
and routes it to a relevant seat. The reply remains advice; the agent may use
or decline it. Voluntary and system-initiated exchanges are labeled
separately. Evaluation answers remain outside the exchange. (Anchor:
`CASCADE-01`)

This is the funding narrative in one sentence: the simple intervention failed
cleanly, the missing behavior became observable, and the program now has a
specific instrument for learning what moves it.
